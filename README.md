# lemonade678.github.io

นามบัตรออนไลน์ — เว็บหน้าเดียว ไฟล์เดียว ไม่มี build step

เว็บนี้เป็น **ตัวย่อ** ของพอร์ตเต็มที่อยู่บน Vercel
กลุ่มเป้าหมายคือ dev ที่กดจากโปรไฟล์ GitHub เข้ามา อยากเห็นเร็ว ๆ ว่าทำอะไรมาบ้าง
แล้วกดเข้าไปดูโค้ดต่อ — ไม่ได้มาอ่านเรียงความ

| | นามบัตร (ที่นี่) | พอร์ตเต็ม |
|---|---|---|
| URL | `lemonade678.github.io` | Vercel |
| ซอร์ส | repo นี้ · `index.html` ไฟล์เดียว | [`Lemonade678/portfolio`](https://github.com/Lemonade678/portfolio) |
| เนื้อหา | ชื่อ + repo ที่เลือกมา + ช่องทางติดต่อ | โปรเจกต์เต็ม ตัวเลข หลักฐาน เดโมที่รันได้จริง |
| ภาษา | อังกฤษล้วน (คนดู GitHub เป็นสากล) | ไทย/อังกฤษ สลับได้ |
| build | ไม่มี | Next.js |

## ปุ่ม "Full portfolio" ชี้ไปไหน

`index.html` ตรง `class="cta"` → **<https://lemonade976.vercel.app/>**
(ตรวจแล้วว่าเปิดได้จริง ทุก asset ตอบ 200)

Vercel ตั้งชื่อ production domain จากชื่อโปรเจกต์ **ถ้าเปลี่ยนชื่อโปรเจกต์เมื่อไหร่
URL นี้จะเปลี่ยนตาม** แล้วปุ่มที่เด่นที่สุดบนหน้านี้จะพาไป 404 เงียบ ๆ
— จำไว้ว่าต้องกลับมาแก้ที่นี่ด้วย

โปรเจกต์เดียวกันยังมี `proudpersonalportfolio.vercel.app` ที่ 307 redirect มาหาตัวนี้
ใช้ก็ได้แต่จะเสียหนึ่ง hop เลยชี้ไปตัว production ตรง ๆ

## Deploy

ไม่ต้องตั้งค่าอะไรมาก เพราะเป็นไฟล์นิ่งล้วน:

1. push ขึ้น `main`
2. repo → **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**
3. รอสักครู่ เว็บจะขึ้นที่ `https://lemonade678.github.io/`

repo ชื่อ `<username>.github.io` เป็น **user site** → เสิร์ฟที่รากโดเมนตรง ๆ
ไม่ต้องตั้ง `basePath` อะไรทั้งนั้น

> ไม่ต้องมี `.nojekyll` เพราะเว็บนี้ไม่มีโฟลเดอร์ที่ขึ้นต้นด้วย `_`
> (ตัวที่ต้องมีคือฝั่ง Next.js ซึ่งเก็บ asset ไว้ใน `_next/` แล้ว Jekyll จะข้ามทั้งก้อน)

## แก้เนื้อหา

ทุกอย่างอยู่ใน `index.html` ไฟล์เดียว แก้แล้ว push ได้เลย ไม่ต้อง build

**รายการ repo เขียนไว้ตายตัวใน HTML ไม่ได้ยิง GitHub API** — ตั้งใจแบบนั้น
เพราะถ้ายิง API คนเปิดเว็บต้องรอ network ก่อนถึงเห็นเนื้อหา ซึ่งขัดกับเหตุผล
ทั้งหมดที่ทำเว็บนี้ให้เบา แลกกับการที่ต้องมาแก้เองเวลาเพิ่ม/ลบ repo

ถ้าเพิ่ม repo ใหม่ ก๊อปบล็อก `<a class="repo">` มาวางแล้วแก้:

| ค่า | ความหมาย |
|---|---|
| `style="--c:var(--blue)"` | สีชื่อ repo และสีขอบตอนเอาเมาส์ชี้ |
| `.dot` background | สีประจำภาษาตามที่ GitHub ใช้ (TS `#3178C6` · Python `#3572A5` · Jupyter `#DA5B0B` · Lua `#000080`) |
| `.star` | จำนวนดาว — ลบทิ้งได้ถ้ายังไม่มี |

## ทำไมไม่ใช้ Next.js เหมือนพอร์ตเต็ม

1. GitHub Pages เสิร์ฟ `index.html` ได้ตรง ๆ ไม่ต้องมี build ไม่ต้องมี Actions
   ไม่ต้องมี `node_modules` — push แล้วขึ้นเลย
2. โหลดจบในครั้งเดียว ไม่มี JS ให้รอ ไม่มี hydration
3. ยิ่งชิ้นส่วนน้อยยิ่งพังยาก อีกสองปีกลับมาแก้ก็แก้ได้ทันที
   ไม่ต้องมานั่งอัปเดต dependency ก่อน

ข้อแลก: ไม่มีปุ่มสลับภาษา และแชร์ component กับพอร์ตเต็มไม่ได้
ถ้าวันหนึ่งสองเว็บนี้เนื้อหาเริ่มไม่ตรงกัน ต้องมาไล่แก้เองสองที่
